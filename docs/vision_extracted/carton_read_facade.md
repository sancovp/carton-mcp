# carton_read_facade

## A text predicate sees the same bytes the facade returns
A `CONTAINS` evaluated server-side and the body the facade returns agree, or the text predicate is not
offered.
A substring predicate over a description matches the words and never the stored link markup.

## THE FACADE ANSWERS A READ NAMING A CODE-GRAPH LABEL
The code graph and the concept store are ONE database. A read naming a File, Function, Class, Module,
Method or Tool node is answered, never refused for not targeting the concept namespace.
A caller the facade broke is repaired in the facade, never by restoring a bare driver for that one caller.

## The facade raises on an outage and prints nothing of its own
The session through which doc-mirror talks to the store suppresses driver notifications at that boundary.
No CLI built on it prints a raw warning, its diagnostic record, its severity or the query it came from
ahead of its answer.
An unreachable store raises as an outage.
Nothing in the store import chain rebinds file descriptor 1. A CLI that reads the board answers on stdout
with no per-bin descriptor guard.

## The registration chokepoint strips at one place
The strip happens at the single registration chokepoint.

## EVERYTHING IS READ ON CARTON
A module is read as its FEATURE NODES, their RANGES, their doc(v) COORDINATE and their doc(m) PROJECTION NODE, all connected. The doc(m) and the doc(v) are the only things read for context, and they are read from THEIR COLLECTIONS. The unit of understanding is the SEALED FEATURE BOUNDARY, never a single file.

## EVERYTHING ON CARTON IS A FULLY CONNECTED GRAPH
Every thing carries its edges to what it is PART OF, what it INSTANTIATES and what it PRODUCES.
