# activate_collection

## The walk filters retired members and preserves chronology
A collection activation serves no member whose thread has been retired.
It returns its members in the order that carries their sequence, never ordered by name.
An activation takes an optional since-boundary and returns only the members after it.

## ACTIVATION RETURNS THE EXACT GRAPH THAT IS ONLY THAT
Collections interpenetrate — a domain has_part a subdomain has_part an entry has_part a concept — so an
unbounded recursive walk over HAS_PART returns the graph rather than the graph that is only that thing.
THE PRIMITIVE IS BOUNDED ACTIVATION: a walk that knows where to stop, by TYPE, by PER-EDGE-KIND DEPTH, or
by a bound STORED ON THE COLLECTION ITSELF.
The bound lives in the walk, not in each caller refusing hub members by hand.

## The walk PROJECTS each member's status
Every member carries a status field in the returned set, so a live member is distinguishable from a
retired one.

## EVERY TRAVERSAL TYPE RUNS OVER THE MANIFOLD, BOUNDED
Every traversal type runs over the manifold automatically, each on a bounded walk.

## COLLECTIONS ARE THE INDEX
A favorites collection and a current-focus collection are held in state and read by every surface.
A favorite is pinned, unpinned, activated and listed as active.
Collections are discoverable by name, by domain, and by relation to a concept or to another collection.
A `Carton_Collection` requires `has_domain`.
Collections relate to each other, so a traversal runs from index to index.
